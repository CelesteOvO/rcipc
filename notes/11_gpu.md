# 阶段 11：GPU 版

**目标：** 把阶段 1–10 的时间步原样搬到 GPU 上，然后和 libuipc 在同一个布娃娃堆上比墙钟时间。

“原样”的意思是：同一个 Newton 循环、同样的能量、行、预条件器、CCD、线搜索、κ 规则，只是每一项都换成在显存里并行算。所以测试可以拿 CPU 版当参照，逐项对比（第 7 节）。

**结论先说：**
- 60 个布娃娃（三角网格，和 libuipc 同一份网格）：每步 14–15 ms，libuipc 不开计时器 209–219 ms，约 **14–15 倍**。8 个布娃娃每步 2.0 ms，约 18–20 倍。
- 旧分支的实现（Warp 版）在同一台机器上每步 10–11 ms，约 **20 倍**，比我们快约 1.4 倍。差距在实现上，不在硬件上（第 9 节）。它的宽相（刚体坐标系里事先分好组）、CUDA graph 已经搬过来了（第 3、12 节），惯性 Hessian 和预条件器改成了组合刚体的写法（第 11 节）；还差 CCD 的分段和 FK（第 9 节末尾）。
- 一路的优化和每一步的测量见第 8 节。这一节是这个阶段最值得看的部分：GPU 上什么慢、为什么慢，大多和直觉不一样。

代码在 `src/gpu/`，接口是 `include/rcipc/gpu.h` 的 `gpu::Stepper`，用法和 `rcipc::step` 一样。

## 1. 数据和数学（`device_model.h`、`devmath.cuh`）

**数据：** `Model` 里的结构体数组（`vector<Body>` 之类）摊平成“每个字段一个数组”（structure of arrays），全部上传到显存。相邻线程读相邻元素时，访存能合并成一次。

上传时检查几个前提，后面的内核都靠它们：
- 刚体按深度优先排序（MuJoCo 本来就是），所以刚体 b 的子树是连续的一段 `[b, bsub_end[b])`；
- 一棵树的自由度、刚体都是连续的一段（`tdof0/tndof`、`tbody0/tnbody`）；
- 一个刚体的顶点、边、三角形都是连续的一段；
- 一个刚体的链上最多 64 个自由度（`CH`），一棵树最多 `TD` 个自由度（布娃娃是 28）。

**数学：** 设备代码里不用 Eigen，`devmath.cuh` 自己写了三维向量、四元数、3×3 矩阵。每个运算都照抄 Eigen 的运算顺序（比如四元数转动向量照抄 `_transformVector`），所以 GPU 和 CPU 的结果只差舍入。

**精度：** 能量、梯度、Hessian、PCG、距离、CCD 全部是双精度。单精度只出现在剔除里，而且都带保守的余量，只会多留不会漏（第 8 节）。

## 2. 运动学和惯性项（`kin.cu`）

| 内核 | 并行方式 | 对应 CPU |
|---|---|---|
| `k_integrate` | 一个线程一个关节 | `integrate` |
| `k_fk`、`k_vertices` | 一个线程一个刚体（从根沿链往下自己算一遍）；一个线程一个顶点 | `forward_kinematics`、`world_point` |
| `k_targets`、`k_inertia_energy`、`k_inertia_gradient` | 一个线程一个刚体，原子加 | `inertia_targets` 等 |
| `k_inertia_hessian` | 一个线程块一棵树 | `inertia_hessian` |
| `k_limits`、`k_limit_ccd` | 一个线程一个关节 | `limits.cc` |

FK 每个线程把祖先重算一遍，省掉了按层同步。布娃娃的链很短（最深 4 层），这样更快。

惯性 Hessian 的一个元素是
$$H_{ij} = \frac{1}{h^2}\sum_b \left( m_b V_{bi}\cdot V_{bj} + a_i \cdot I^{w}_b a_j \right),$$
只对链上同时有 i 和 j 的刚体求和，也就是 `[max(bi, bj), min(bsub_end[bi], bsub_end[bj]))` 这一段。线程块先把这棵树每个刚体的质心、世界系惯量 $R I R^T$，和每个自由度的轴、锚点放进共享内存（各算一次），再分摊上三角的元素。最早的版本每个元素都对每个刚体重算 $R I R^T$，一次要 170 μs，改完 56 μs。

## 3. 接触（`contact.cu`、`narrow.cu`、`rows.cuh`）

**检测分三层**，和 CPU 版 `for_each_candidate` 的规则一样，所以找到的接触一样：
1. **刚体对**（`k_body_pairs`）：一个线程一对刚体，包围盒按 dmax 放大后重叠的写进列表。
2. **剔除**（`narrow.cu`，在刚体坐标系里，第 3.1 节）。
3. **精确判断**（`k_detect_exact`）：一个线程一个候选，双精度的 `make_pt` / `make_ee`，d < dmax 的追加到接触列表。

### 3.1 在刚体坐标系里剔除

刚体是刚性的：它的三角形、边在自己的坐标系里永远不动。所以上传模型时（`stepper.cc` 的 `build_chunks`）就把每个刚体的三角形和边在它自己的坐标系里算好单精度的盒子（含半径，向外取整），再按空间分组：按盒子中心坐标跨度最大的轴在中位数处一分为二，直到每组不超过 32 个。组的盒子是组里各个盒子的并，刚体的总盒子是各组的并。这些以后都不用再算。这是上一个分支的做法（`pq_chunk`）。

每次检测：
- **`k_pair_cull`**，一个 warp 一对刚体 (a, b)。先用双精度算两个相对变换（a 到 b、b 到 a，$R = R_b^T R_a$，$t = R_b^T(x_a - x_b)$），转成单精度。再把三种查询换到对方的坐标系里：a 的顶点对 b 的三角形，b 的顶点对 a 的三角形，a 的边对 b 的边。和对方的总盒子比，按 dmax（加余量）重叠的写进工作列表。
- **`k_work_cull`**，一个工作项 8 个线程。先和对方的各组盒子比，命中的组里由 8 个线程分摊各个图元的盒子测试，再算单精度距离，减去余量还小于 dmax + 半径的写成候选。

单精度的盒子都向外取整，距离带余量 $10^{-5}(1+R)$ 米（R 是这对刚体世界坐标的最大绝对值，比刚体坐标系里的坐标和相对平移都大），所以只会多留不会漏。

**每个接触的各项**（`k_contact_terms`）一个线程一个接触：能量、梯度（含 mollifier 的导数）、行、曲率上界，原子加到全局数组。摩擦（`k_friction_lag`、`k_friction_terms`）一样，一个线程一个摩擦接触。

**行按力旋量存（`rows.cuh`）。** CPU 版的一行存的是链上每个自由度的值。GPU 版换了一种等价的存法：一侧的模板顶点合起来是 $P = \sum w X$、$W = \sum w$，方向 dir、系数 s 时，这一侧在自由度 d 上的值是
$$s\,\mathrm{dir}\cdot\big(a_d\times(P - W o_d)\big) = a_d\cdot(\tau - o_d\times f)\ (\text{转动}),\qquad s W\,\mathrm{dir}\cdot a_d = a_d\cdot f\ (\text{滑动}),$$
其中 $f = sW\,\mathrm{dir}$、$\tau = s\,P\times\mathrm{dir}$ 是关于世界原点的力和力矩。所以一侧只要存刚体编号和 $(f, \tau)$ 六个数。为什么要这样存，见第 5 节。

## 4. CCD（`ccd.cu`）

和 CPU 版 `curved_ccd` 一样分段：段长由最大的加速度界定，某一对要求更短的段时缩短重做。分段的循环在主机上，每一段在 GPU 上做：
1. **地面**（`k_ground_ccd`）：一个线程一个顶点，闭式解。
2. **刚体对**：扫掠盒按两侧的矢高 $A_b\,\ell^2/8$ 放大后重叠。
3. **剔除**（`narrow.cu`，和检测共用，在段起点的刚体坐标系里）：阈值换成下面的 T；通过距离测试的再用单精度的世界坐标（段起点、终点的顶点，`launch_to_float`）把 CPU 版的盒子规则先查一遍。
4. **ACCD**（`k_ccd_exact`，一个线程一个候选）：先用双精度把 CPU 版的盒子规则原样复核，通过的才做 ACCD。

**剔除为什么不改变结果。** CPU 版的规则是盒子重叠（顶点的扫掠盒和对方刚体、和三角形都按 ξ 重叠才做 ACCD）。GPU 版在这之前多剔一遍：段起点的距离 $d_0$ 足够大的对，ACCD 第一步就会返回 1，什么也不改。看 `accd_pair`：
- 它在 $\xi > d_0/2$ 时要求缩短段长，所以要 $d_0 \ge 2\xi$；
- 第一步 $t_1 = c(d_0 - \xi)/\ell$，$t_1 \ge 1$ 就返回 1，所以要 $c(d_0-\xi) \ge \ell$；
- $\ell = l_a + l_b$，每一项是某个顶点的位移减去四个顶点的平均位移，不超过 $2D_{\max}$（$D_{\max}$ 是两个刚体的顶点在这一段里的最大位移，`k_body_disp`）。

所以 $d_0 \ge T = \max(2\xi,\ \xi + 4D_{\max}/c)$ 就可以跳过（T 再放大 1%，盖住双精度的舍入）。$d_0$ 在段起点的刚体坐标系里用单精度算，减去余量。通过的再用双精度把 CPU 版的盒子条件原样查一遍。做 ACCD 的对是 CPU 版的一个子集，少掉的都是 ACCD 什么也不改的，所以结果完全一样（测试 `Ccd.MatchesCpu` 要求差 1e-12 以内）。

**ACCD 的提前停止。** t 只增不减。别的对已经找到的截断位置 `*tmin` 不比当前的 t 大时，这一对最后的结果也不会更小，可以停。这也不改变结果。

## 5. 线性求解（`solver.cu`、`pcg_coop.cu`）

### 5.1 H p 的行部分

$H p = H_k p + \sum_r D_r\, r_r (r_r\cdot p)$。CPU 版逐个自由度算 $r_r\cdot p$，再逐个自由度加回去。在 GPU 上这意味着每行对链上每个自由度原子加一次（布娃娃一行约 26 次），而一个布娃娃的所有行都要加到它的 6 个根自由度上：几百次原子加挤在同几个地址上排队。

按力旋量算（第 3 节的存法）：
1. **速度旋量：** 每个刚体 $\omega_b = \sum_{\text{转动 } d} p_d a_d$，$v_b = \sum_{\text{转动 } d} p_d (o_d\times a_d) + \sum_{\text{滑动 } d} p_d a_d$（只对 b 的链求和）。一侧的 $r\cdot p$ 就是 $f\cdot v_b + \tau\cdot\omega_b$。
2. **散射：** $c_r = D_r (r_r\cdot p)$，把 $c_r(f, \tau)$ 原子加到两侧的刚体上（每行 12 次，分散在各个刚体上）。
3. **子树之和，投影：** 自由度 d 在刚体 b' 的链上，当且仅当 b' 在 d 所在刚体的子树里。所以 d 得到的是 $S_d\cdot \sum_{b'\in \text{子树}} (F, T)_{b'}$，其中运动向量 $S_d = (o_d\times a_d,\ a_d)$（转动）或 $(a_d,\ 0)$（滑动）。

这是旧分支协作 PCG 的做法（README 里的 wrench scatter），本质上是 Featherstone 算法里 $J p$ 和 $J^T f$ 的写法。

### 5.2 预条件器

和 CPU 版一样，每棵树一块：$P_t = H_{k,t} + \sum_r D_r [r_r r_r^T]_{tt}$，Jacobi 缩放、加 1e-10 的对角岭、Cholesky（CPU 版用 LDLT，解只差舍入）。

两点不同：
- **行的累加**先在每个刚体上累加一个 6×6，再按子树求和（第 11 节）。最初的写法是一个 warp 一行（`k_precond_rows`，树太大、放不进共享内存时还用它）：每个 lane 算行里的一个元素，再用 shuffle 两两相乘，只加下三角（分解只读下三角）。
- **分解完把逆显式算出来**：$P_t^{-1} = S (L D L^T)^{-1} S$。PCG 每次迭代都要用一次 $P^{-1}$，有了逆就是一个小的稠密矩阵乘向量，全并行；前代、回代是串行的。分解在共享内存里做（第 11 节）。

### 5.3 两种 PCG

- **主机循环**（`run_pcg`）：和 CPU 版 `pcg` 一行一行对应，每次迭代几个内核、读回两个点积。简单，测试用它当参照。
- **协作内核**（`run_pcg_coop`，默认）：整个循环一个内核。协作启动保证所有块同时驻留，于是可以 `grid.sync()`。每次迭代 3 次全局同步：
  - **A**（一个 warp 一棵树）：$p = z + \beta p$；速度旋量；$H_k p$ 和 $p^T H_k p$。
  - **B**（一个线程一行）：$s = r\cdot p$，$p^THp$ 加上 $D s^2$，散射力旋量。
  - **C**（一个 warp 一棵树）：子树之和、投影；$x$、$r$ 更新；$z = P^{-1} r$；$r^T z$。

  这棵树的 p、r、Ap 和 $S_d$ 放在负责它的 warp 的共享内存里，整个求解期间不离开。$p^T H p$ 直接按 $p^TH_kp + \sum D s^2$ 累加，省掉一次点积和一次同步。

## 6. 主机这一侧（`stepper.cc`）

Newton 循环和 CPU 版 `step()` 一行一行对应。和 CPU 版不同的地方：
- **复用线搜索的检测：** 线搜索最后一次试探的正是接受的 α，它的 FK 和接触都在显存里。所以更新时直接交换 F 和 Ft 的指针，不再做一遍 FK 和检测。CPU 版重新算，结果一样。
- **少读回：** 每次从显存读一个数，都要等 GPU 把前面的活做完，而主机发下一批内核之前 GPU 是空着的。所以能一起读的尽量一起读：
  - 组装的能量、PCG 的迭代次数、收敛判断的位移一次读回；
  - 限位 CCD 和分段无关，先发出去，结果跟着 CCD 的第一段一起读回；
  - κ 调整用的最小距离在线搜索最后一次算能量时顺便算，和能量一起读回；
  - 刚体对、候选、接触的个数留在显存里，内核自己读，最后一次读回检查容量；
  - 往显存里写一个数用一个线程的小内核，不用同步的拷贝。
- **容量：** 刚体对、候选、接触的数组按需扩容。个数超过容量时扩容后重做这一次检测（或这一段 CCD）。行数每次组装都在变，按 1.5 倍扩容（只扩到刚好够用时，接触一多就要重新分配，而 `cudaFree` 会让整个设备同步）。
- **计时：** `Timers` 分段计时，每段结束同步一次。量墙钟时间时用 `set_timing(false)` 关掉（`scene_demo timing=0`）。
- **CUDA graph（默认）：** 上面这些是逐个发射的写法。默认的写法把一个 Newton 迭代录成一张图，CCD 的分段和线搜索的回溯在设备上循环，每个迭代只回主机一次（第 12 节）。`set_graphs(false)`（`scene_demo graph=0`）或者传了 `trace` 时用逐个发射。

和 CPU 版的差别（`gpu.h` 的注释里也写了）：
- 原子加的顺序不固定，求和的舍入每次不一样。所以 GPU 和 CPU（以及 GPU 两次运行之间）只在舍入的量级上一致，混沌的场景跑久了轨迹会分开；
- 总是 PCG（`StepParams::solver` 被忽略），不支持 `check_iterates`；
- `StepResult::min_distance` 只看 d̂ 以内的接触。

## 7. 测试（`tests/test_gpu.cc`）

没有 CUDA 设备时测试自动跳过。

| 测试 | 检查什么 | 容差 |
|---|---|---|
| `Fk.MatchesCpuOnZoo` | 各种关节的 FK | 舍入 |
| `Terms.*`（5 个场景） | 能量、梯度、稠密的 H（树块加所有行的外积）、接触数、摩擦数 | 舍入 |
| `Precond.MatchesBlockInverse` | 树块预条件器的逆和 CPU 版组装的 H 的块逆一致；场景里有两侧在同一棵树里的行（第 11 节的交叉项） | 1e-8 |

| `Step.*MatchesCpu` | 落地的盒子、堆叠、布娃娃，整段轨迹；CUDA graph 版和逐个发射的各比一次 | 1e-8 到 1e-5 |

`Terms` 测试里 GPU 的行要先展开成逐个自由度的值（`launch_rows_expand`），再拼成稠密的 H。所以第 3 节的力旋量存法也被逐项检查过。

## 8. 优化的过程

场景：60 个三角网格布娃娃（`compare/libuipc/ragdolls_60_mesh.xml`，660 个刚体，nv = 1680，21960 个顶点、61920 条边、41280 个三角形），h = 0.01，d̂ = 1 cm，μ = 0.2，ε_v = 0.01，容差 0.05 m/s，半隐式停止，3 s。每一行是在上一行的基础上加一项改动，每步的毫秒数（布娃娃堆是混沌的，同一个版本跑几次会差 ±5%）：

| 改动 | ms/步 | 为什么 |
|---|---|---|
| 直接移植（一个线程块一对刚体，主机循环的 PCG） | 65.6 | — |
| 图元的单精度盒子先剔 | 53.1 | 双精度的盒子每对图元都要从顶点重算 |
| 协作内核 PCG；复用线搜索的检测 | 47.3 | 主机循环每次迭代 7 个内核、2 次读回 |
| 预条件器显式求逆；每次迭代 3 次全局同步 | 33.7 | 一个线程一棵树的前代、回代是串行的 |
| 候选排队，攒够一批全块一起做双精度 | 25–28 | 一个 warp 里只有约 18% 的线程有活，双精度单元空等 |
| 一个 warp 一对刚体；单精度距离剔除 | 23.6 | 每对平均只剩约 266 个组合，块内同步和访存延迟占了大头 |
| 剔除和精确判断拆成两个内核 | 24 | 剔除快了一半，ACCD 的长尾露出来了（见下） |
| 行按力旋量存 | 23.5 | 根自由度上的原子加排队 |
| PCG 的树数据放共享内存，预先算 $S_d$ | 20.7 | 每次迭代反复从显存读写 |
| 惯性 Hessian 的刚体数据放共享内存，按对称只算一半 | 约 20 | 每个元素都重算 $R I R^T$ |
| 预条件器的行一个 warp 一行 | 18.5 | 一个线程一行，26×26 次原子加串行 |
| 合并读回，个数留在显存 | 17.6 | 每个 Newton 迭代 13 次同步，GPU 空等 |
| 剔除改在刚体坐标系里，事先分好组（旧分支的做法），一个工作项 8 个线程 | 16.5 | 每次检测都重算全部图元的世界坐标系盒子，每对刚体把两边的图元全过一遍 |
| 惯性 Hessian、预条件器的行改成组合刚体的写法；分解在共享内存里做 LDLᵀ；行数按 1.5 倍扩容（第 11 节） | 15.3–16.5 | 每个元素对子树里每个刚体重算一遍；几百行抢着原子加同几个根元素；每列每个线程都做一次双精度除法；每步 3 次 `cudaFree` |
| CUDA graph：一个 Newton 迭代一张图，CCD 分段和线搜索在设备上循环（第 12 节） | 13.9–15.1 | 每个迭代约 6 次同步、60 次发射，每次同步以后 GPU 都要等主机重新喂活 |
| CCD 的加速度界和紧界取小（CPU、GPU 都改，阶段 5 笔记第 6 节） | 14.9–15.6（同一时段静态界 14.9–16.9） | 静态界的力臂是沿整条链的路径长度，段太短：每个迭代 1.78 段 → 1.52 段 |

**这次学到的几件事：**
1. **消费级显卡的双精度只有单精度的 1/64。** RTX 4060 Ti 的双精度峰值约 0.35 TFLOPS，一个 SM 每个时钟只能做 2 个双精度乘加，一条 warp 指令要 16 个时钟，不管有几个 lane 在干活。所以双精度的活要让 32 个 lane 都满着（排队、两遍内核），能用单精度剔掉的就先剔掉。
2. **很多内核不是算得慢，是在等。** 一个线程块一对刚体时，每对只有几百个组合，时间都花在块内同步和访存延迟上；一个 warp 一对、减少共享内存、提高占用率才有用。
3. **原子加挤在同一个地址上会排队。** 布娃娃的根自由度在每一行里都有，力旋量的写法把原子加分散到各个刚体上。
4. **主机读回一个数，GPU 就空一次。** 合并读回之前，GPU 上的内核一共 15 ms，墙钟 18.5 ms，差的就是这些空档。
6. **刚体的几何在自己的坐标系里不动。** 能事先算好的（盒子、分组）就不要每次检测都算。搬这一项时，CCD 起初反而变慢了：新的剔除只用了距离测试，丢掉了原来的单精度扫掠盒测试，进到双精度复核的候选多了很多。把扫掠盒测试加回去，再让一个工作项用 8 个线程，才真正变快。
5. **工具：** Nsight Systems（`nsys`）能看每个内核的时间，这台机器上能用。Nsight Compute 要管理员权限才能读性能计数器（`ERR_NVGPUCTRPERM`），所以内核内部的分析是用 `clock64()` 计时、原子加计数做的（临时加的代码，没有留在仓库里）。
   这里装的 Nsight Systems 2024.6 用的是 CUDA 12.6 的追踪库（驱动是 13.2），录了条件节点的 CUDA graph 在它下面一启动程序就退出，所以图版的内核时间只能用 `graph=0` 量。
7. **双精度除法是软件实现。** 消费级显卡上一次双精度除法是十几条双精度指令。分解里每一列每个线程都算一次 $1/d_j$、最后求逆时最内层做 $n^3/6$ 次除法，就占了分解的一半；改成每列只算一次存进共享内存，分解从 114 μs 降到 57 μs。
8. **同步藏在不起眼的地方。** `grow_rows` 每次只扩到刚好够用，接触数一涨就重新分配：每步约 3 次 `cudaMalloc`、`cudaFree`，而 `cudaFree` 会等整个设备做完。Nsight 的 API 统计里才看得出来。

**ACCD 的长尾。** 贴着滑动的一对，$d_0$ 很小、相对位移 $\ell$ 不小，每步只前进 $c(d-\xi)/\ell$，要迭代上百次。CPU 上一次距离计算几十纳秒，无所谓；GPU 上一个线程的双精度迭代一次约 1 μs，这一个线程就拖住了整个内核。`k_ccd_exact` 每段约 140–170 μs，大部分是在等这几个线程。算法是 CPU 版的，这里没有改。

已经搬过来的：宽相（第 3.1 节）、CUDA graph（第 12 节）、按窗口求 CCD 的候选（第 13 节）；惯性 Hessian 和预条件器的行改成了组合刚体的写法（第 11 节），惯性 Hessian 现在比旧实现还省。FK 不改变结果，可以直接搬。CCD 的分段方式和接触岛预条件器会改变算法（截断位置、PCG 的解都会不同），要先在 CPU 版改，GPU 版再跟上。

## 11. 组合刚体的写法：惯性 Hessian 和预条件器的行（`kin.cu`、`solver.cu`、`rows.cuh`）

**问题。** 惯性 Hessian 的元素 $H_{ij}$ 要对“链上同时有 i 和 j 的刚体”求和，每个刚体一次叉乘加一次 3×3 乘法；根自由度在每个刚体的链上，所以一棵 11 个刚体的树里，根附近的元素都要算 11 遍。预条件器的行更糟：每行把 $D\,r r^T$ 原子加进树块，一行约 26×26/2 次；一个布娃娃的几百行全都落在它根部的那几个元素上，排队。

**想法。** 两者都是“一个只和某个刚体有关的 6×6，经过它链上的自由度展开”。自由度 d 的空间轴是 $s_d = ((o_d - \text{ref})\times a_d,\ a_d)$（转动）或 $(a_d, 0)$（滑动），关于同一个参考点。那么：
- 速度旋量是 $\sum_d p_d s_d$，所以刚体 b 的动能贡献是 $s_i^T I_b s_j$，$I_b$ 是它的 6×6 空间惯量：
$$I_b=\begin{bmatrix} m\,\mathbf 1 & -m[c]_\times\\ m[c]_\times & I_c + m(|c|^2\mathbf 1 - cc^T)\end{bmatrix},\qquad c = \text{质心} - \text{ref}$$
- 一行落在刚体 b 上的那一侧是力旋量 $w = (f,\ \tau - \text{ref}\times f)$，它在 d 上的值是 $s_d\cdot w$，所以这一侧对树块的贡献是 $s_i^T (D\,ww^T) s_j$。

i、j 都在刚体 b 的链上，当且仅当 b 在两者里较深的那个刚体（lo）的子树里。所以先把每个刚体的 6×6 在子树上加起来，$\bar I_{lo} = \sum_{b\in\text{子树}(lo)} I_b$，每个元素就只是一次二次型：
$$H_{ij} = \frac{1}{h^2}\, s_i^T \bar I_{lo}\, s_j$$
这就是 Featherstone 的组合刚体算法（CRBA）。和原来是同一个和，只是换了求和的顺序，结果只差舍入（`Terms.*`）。参考点取树根：坐标小，舍入小。

**两侧在同一棵树里的行。** 这时行的值是 $u + v'$（u 在 A 侧的链上，v' 在 B 侧的链上），外积里还有交叉项 $D(uv'^T + v'u^T)$。两条链共有的那一段（公共祖先 L 的链）上，交叉项是 $s_i^T D(w_Aw_B^T + w_Bw_A^T) s_j$，和单侧的项同一个形状，所以也加到 $W_L$ 上交给子树求和；剩下的对（至少有一个自由度在 L 下面）由 `k_precond_cross` 逐对原子加。相邻的两个刚体（A 的父刚体是 B）时 L = B，剩下的只有 A 自己的关节那几个自由度乘 B 的链。网格布娃娃的相邻刚体之间都有接触，这一步把交叉项的内核从 62 μs 降到 44 μs。

**分解。** 在共享内存里做 LDLᵀ（右视）：第 j 列的主元就是 $B_{jj}$，后面整块 $B_{ik} \mathrel{-}= B_{ij}B_{kj}/d_j$，块里的线程分摊，一列一次同步；$1/d_j$ 由更新到 $(j{+}1, j{+}1)$ 的那个线程顺手算好存起来（双精度除法很贵，第 8 节第 7 条）。然后 $Y = L^{-1}$（一个线程一列），$P_t^{-1} = S\,Y^T D^{-1} Y\,S$。

**结果**（每次调用，60 个布娃娃）：

| 内核 | 之前 | 之后 |
|---|---|---|
| 惯性 Hessian | 56 μs | 20 μs |
| 预条件器：行（逐行外积 → 每个刚体的 6×6 + 交叉项） | 133 μs | 42 + 44 μs |
| 预条件器：分解求逆 | 68 μs | 57 μs |

树太大、放不进共享内存时（`precond_shared_ok`、`launch_inertia_hessian`）还用原来的写法。测试 `Precond.MatchesBlockInverse` 直接比预条件器的逆，场景里有两侧在同一棵树里的行。

## 12. CUDA graph 版的 Newton 迭代（`iter.cu`、`stepper.cc` 的 `record_graph`）

**问题。** 逐个发射的 Newton 迭代（第 6 节）每次要同步约 6 次：收敛判断 1 次，CCD 求 $A_{\max}$ 1 次，每一段 CCD 1 次（平均 1.8 段），线搜索每次试探 2 次（检测的计数、能量）。每次同步以后 GPU 都空着，直到主机发下一批内核；一个迭代还要发约 60 个内核，Windows 上每次发射 5–8 μs。Nsight 里每步约 85 个 20–200 μs 的空档，加起来约 2.7 ms。

**做法。** 一个 Newton 迭代录成一张图：

```
组装 → 预条件器 → 协作 PCG → 收敛判断 → CCD 的开头
  WHILE（CCD 的分段）：积分到段终点、FK、地面 CCD、IF（不在候选窗口里：宽相、剔除）、复核和 ACCD → 判断（缩短 / 截断 / 前进）
线搜索的开头
  WHILE（回溯）：积分到 α、FK、检测、能量 → 判断（能量降了就停，否则 α 减半）
接受试探点
```

- **判断在设备上。** 每个判断是一个单线程的小内核（`iter.cu`），读写显存里的 `DIter`，和逐个发射的 `step()` 里的那几行一一对应；它同时把“循环要不要继续”写进条件节点（`cudaGraphSetConditional`）。
- **会变的数放在显存里。** 图录好以后内核的参数就固定了。每次迭代会变的数（积分的步长、段长、κ、接触数、行数）改成 `DScalar` / `DCount`（`device_model.h`）：逐个发射时照常传值，图里传 `DIter` 里的地址。内核的网格按容量开，从显存读个数。
- **指针固定，所以拷贝。** 逐个发射时交换 F 和 Ft、Fa 和 Fb 的指针；图里的指针是写死的，只能拷（一次约 0.6 MB，几微秒）。
- **放不下时作废重来。** 任何缓冲区放不下时，判断内核标记溢出，这次迭代不接受试探点。主机扩容、重新检测当前点的接触（线搜索把它们覆盖了），重录以后再发一次（`Step.GrowsBuffersMidStep`）。缓冲区的指针或容量一变，版本号 `g_buf_gen` 就加一，图跟着重录。
- **每个线程的默认流。** 旧的全局默认流不能捕获。CMake 给 `.cu` 加 `--default-stream=per-thread`，给 `.cc` 定义 `CUDA_API_PER_THREAD_DEFAULT_STREAM`，于是不带流参数的发射都排在 `cudaStreamPerThread` 上，可以捕获。
- **一个迭代一次读回。** 发图之前异步写 κ、nc、nf（`DIter` 的前三个字段），发图，读回整个 `DIter`。κ 的调整、半隐式停止还在主机上。

图版要协作 PCG（`run_pcg_coop` 在图里照样能捕获），传了 `trace` 时用逐个发射（每次迭代要多读最小距离）。`set_graphs(false)` / `scene_demo graph=0` 关掉。

**结果。** 每个 Newton 迭代从 2.38–2.63 ms 降到 2.25–2.38 ms（60 个布娃娃，交替各跑 3 次；逐个发射的那三次波动大），每步约 14–15 ms。剩下的约 0.3 ms 估计是：每次迭代一次同步、约 60 个图节点在设备上的启动延迟、几个单线程判断内核和两处拷贝。省得比预想的少：逐个发射时内核本身已经约 2.0 ms/迭代，主机这一侧能省的本来就只有三四百微秒。

## 13. 按窗口求 CCD 的候选（`narrow.cu` 的 `k_pair_cull`、`stepper.cc` 的 `ccd()` 和 `record_graph`）

**问题。** 每个 Newton 迭代平均 1.5 段 CCD，每一段都重做刚体对和剔除（第 4 节）。多出来的段几乎都是缩短重做的段，和缩短以后接着往前走的段，它们都落在前面某一段的范围里。60 个布娃娃里临时加计数器量过：2741 段里有 948 段落在上一次求候选的那一段里，每个迭代约 0.5 段。旧实现每个迭代只求一次候选，细分时只重做 ACCD。

**做法。** 求候选的那一段 $[w_0, w_1]$ 当作窗口，剔除的阈值和盒子的余量放大到盖住窗口里的任何一段 $[s_0, s_1]$。之后落在窗口里的段跳过刚体对和剔除，直接拿窗口的候选做复核和 ACCD。复核（`k_ccd_exact`）用的还是这一段自己的扫掠盒和矢高，规则不变，所以结果和每段都求的一模一样（`Ccd.MatchesCpu` 两种都比）。

放大多少。记 $L = w_1 - w_0$，$D_b$ 是窗口两端之间刚体 b 的顶点的最大位移，$\xi_b = A_b L^2/8$，$\xi = \xi_a + \xi_b$。
- **几个界。** 顶点在窗口里离弦不超过 $\xi_b$（矢高），弦又在两个端点的盒子里，所以：
  - 任何时刻离 $w_0$ 处的位置不超过 $M_b = D_b + \xi_b$；
  - 在一段里的位移不超过 $D_b + 2\xi_b$；
  - 一段的扫掠盒在窗口的扫掠盒向外放大 $\xi_b$ 以内。
- **剔除的阈值。** 第 4 节一段的阈值是 $\max(2\xi_s, \xi_s + 4D_s/c)$，其中 $\xi_s \le \xi$，$D_s \le \max_b(D_b + 2\xi_b)$。段起点的距离比 $w_0$ 处的距离至多小 $M_a + M_b$。所以窗口取
$$T_w = 1.01\Big(\max\big(2\xi,\ \xi + 4\max_b(D_b + 2\xi_b)/c\big) + M_a + M_b\Big)$$
$w_0$ 处距离不小于 $T_w$ 的对，在窗口里任何一段的起点上都不小于那一段的阈值，ACCD 第一步就返回 1，剔掉不改结果。
- **盒子规则**（第 4 节，CPU 版的规则）。一段的余量 $\xi_s$，加上两侧的盒子各向外放大的 $\xi_a$、$\xi_b$，合起来不超过 $2\xi$。刚体对的余量 $\xi$ 也要换成 $2\xi$，等价于把段长放大 $\sqrt 2$ 倍传给 `launch_body_pairs`。代码里用 1.42，多留一点盖住舍入。

一段不落在当前窗口里时，它自己就是新窗口；扩容时窗口作废。逐个发射时由主机判断；图里由 `k_ccd_seg_begin` 判断，求候选的几个内核放在一个 IF 条件节点里（WHILE 的循环体里再套一个条件节点）。`set_ccd_reuse(false)` / `scene_demo reuse=0` 关掉。

**结果：** 求候选的段从每个迭代 1.50 段降到 0.97 段，内核时间却几乎没变。下表是 60 个布娃娃、`graph=0`、Nsight 量的每次 CCD 调用（μs；两次运行的轨迹不一样，段数也略有不同）：

| 内核 | 每段都求（1.71 段） | 按窗口求（1.77 段，求候选 1.0 次） |
|---|---|---|
| 刚体对 | 54（每次 32） | 34（每次 33） |
| pair cull | 67（每次 40） | 40（每次 40） |
| work cull | 145（每次 85） | 167（每次 166） |
| 位移、转单精度 | 23 | 13 |
| 复核和 ACCD | 341（每段 200） | 375（每段 213） |
| 地面、初值 | 12 | 12 |
| 合计 | 642（每段 376） | 641（每段 362） |

按每段算省了约 4%，约每步 0.1 ms，在 ±5% 的波动里量不出来（图版墙钟：14.0、15.4 对 15.2、15.5 ms/步）。逐个发射时 CCD 的计时从每个迭代 0.78–0.82 ms 降到 0.73 ms，那是少发了内核、少了几次同步。8 个布娃娃上是 2.1 对 2.4 ms/步（各跑两次），但两边的轨迹不一样（每个迭代 0.70 对 0.75 段，PCG 也少一点），不全是这一项的功劳。

两种写法的结果逐位相同：临时让每次 CCD 两种都算一遍，在 8 个和 60 个布娃娃上一共比了 1325 次，没有一次不同。轨迹会分叉，是因为 GPU 上别处的原子加顺序每次不一样。

**为什么省得少。** 窗口的阈值比一段的大：$\xi \ll D$ 时 $T_w \approx 6.4D$，一段的是 $4.4D$（c = 0.9）；$\xi$ 和 $D$ 相当时差得更多。所以每次 work cull 的工作量翻了一倍（85 → 166 μs），复核的候选也多了 6%。每个迭代只有约 0.5 段能复用，省下的 0.5 × 167 μs，被放大的窗口（每次多约 80 μs）抵掉了大半。

**旧实现的窗口为什么便宜。** 它的剔除规则不同：$w_0$ 处距离超过 $M_a + M_b$ 的对，在窗口里够不着，直接不查。这条规则对整个窗口本来就成立，不用放大。代价是被剔掉的对，如果让 ACCD 来查，可能返回 $t < 1$（ACCD 是保守的），所以截断位置和“对所有对做 ACCD”不一样，剔除规则成了算法的一部分。我们的规则只剔掉 ACCD 第一步就返回 1 的对，GPU 和 CPU 的结果逐位一致，代价就是窗口要放大。另外它不往 $s_{\text{end}}$ 后面走，没有“缩短以后接着走”的段。

**剩下的大头**是复核和 ACCD：每段约 200 μs，占 CCD 内核时间的一半以上。这个内核里一个线程做一对的整个 ACCD 循环，猜测是少数几对迭代很多次的拖住了整个内核（贴着运动的点–三角形，思考题 4）。这一点还没量。
